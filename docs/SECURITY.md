# 凭据与本机访问

## 凭据分层

1. **提供商 OAuth 凭据**：保存在网关运行目录的 auth，不传给管理网页；刷新接口响应需在后端丢弃敏感对象。
2. **网关 API 密钥**：供酒馆或其他客户端调用模型。
3. **网关管理密码**：供管理后端调用 v8 Management API，权限高于普通 API 密钥。
4. **应用访问密钥**：仅在同一手机的管理服务私有文件与安卓应用私有 files 目录之间配对，不写入 APK。

密钥查看接口只允许已认证会话、同源 JSON POST、自定义请求头和显式确认，并只返回第2或第3层。它不会返回提供商 OAuth token 或应用配对密钥。该功能不能抵抗已 root 的攻击者或获准查看密钥的设备使用者。

## 默认防护

- 管理服务只绑定 IPv4 loopback，Host 严格校验。
- Bootstrap 通过自定义请求头接收应用密钥；建立 HttpOnly、SameSite=Strict cookie。
- 写操作需要固定 Origin、自定义头及 JSON Content-Type。
- 返回内容使用 no-store，静态前端使用 CSP、拒绝 frame 嵌入。
- 无任意系统命令、任意目标 URL 或通用凭据代理 API；服务重启只有两个固定单元。
- OAuth 只允许固定提供商，回调校验协议、loopback 目标、端口、路径和当前 state；同提供商操作排队。
- 设备码 CLI 输出只在内存有界解析设备 URL／码，不输出原始日志与账号文件名；可取消并有超时。
- 诊断只含计数及服务状态；常规账号响应不传 account、metadata、path 或原始刷新对象。
- 安卓关闭备份与 WebView 调试；外链只允许明确的官方 HTTPS 域并交系统浏览器。

## 使用者责任与边界

- 不向公共网络开放管理服务；不要把认证 cookie、回调链接或真实配置提交到 Git。
- 单独为酒馆配置登录与网络访问控制；酒馆公开并不等于管理端公开，但共享酒馆仍可能共享付费额度。
- 复制到剪贴板后的密钥由系统管理；前端隐藏不会清空所有剪贴板历史。
- Android 处于解锁状态时，能打开管理应用的人可能主动查看密钥；本版本未增加生物识别门禁。
- 默认模式只适配一个酒馆 default-user。多用户、TLS反代与跨设备远程管理不是默认模式。
- `.gitignore` 不能保护已跟踪的文件；已泄漏凭据必须轮换，不能只从最新快照删除。
- 发布扫描为静态启发式检查，不保证覆盖全部个人隐私和供应链风险。

## 本地验证

```sh
npm run check
npm test
npm run privacy:check
```

上报问题时提供脱敏错误类型、HTTP 状态与版本即可；不要上传私有目录、授权 URL 查询串、账户截图、访问 token 或签名材料。
